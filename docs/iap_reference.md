# Solist-AI IAP ファームウェア — 開発キットユーザーガイド

本ドキュメントは、**gene solist-ai 開発キット** に含まれる Solist-AI モジュール
(ROHM/Lapis ML63Q2537 搭載) の IAP (In-Application Programming) ファームウェア
を利用して、ユーザ自作のファームウェアをモジュールへ書き込むための手順を
説明する。

IAP ファームウェアは出荷時に Solist-AI モジュールへ書き込み済みである。
開発キットのユーザは、モジュールを **IAP モード** で起動し、UART 経由で
新しいファームウェアイメージを送り込むだけで書き換えが完了する。

---

## 1. IAP を使う利点

- **デバッガ不要でファームウェアを書き換えられる。** J-Link 等の
  デバッグプローブを接続する必要はない。用意するのは PC、USB-UART
  変換ボード、Solist-AI モジュール本体のみ。
- **エンドユーザ環境でも更新できる。** シリアル通信さえ張れば、
  現場に置いたモジュールに対しても新しいファームウェアを配布できる。
- **転送プロトコルは標準の XMODEM-CRC。** Windows の Tera Term、
  Linux の `sx` コマンドなど、既存のシリアルツールがそのまま使える。

## 2. 準備するもの

| 項目                       | 用途                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| Solist-AI モジュール       | 更新対象                                                          |
| USB-UART 変換ボード        | PC ↔ モジュール側面 4pin UART コネクタの中継                      |
| 4pin ジャンパ配線          | 変換ボードとモジュールを接続                                       |
| PC (Windows または Linux)  | Windows: Tera Term / Linux: `sx` (lrzsz パッケージ) 等             |
| ユーザファームウェア `.bin`| 書き込む対象イメージ (制約は §6 を参照)                            |

USB-UART 変換ボードは 3.3V TTL レベルに対応したものを使用すること。

## 3. モジュールを IAP モードで起動する

Solist-AI モジュールには **Reset Button** と **IAP mode Button** の 2 つの
ボタンがある。以下の順序で操作することで IAP モードに入る。

1. **Reset Button を押したままにする。**
2. Reset Button を押したまま、**IAP mode Button も押す。** 両方押した
   状態を維持する。
3. **先に Reset Button を離す。** IAP mode Button はまだ押したまま。
4. モジュールが起動し始めるので、その状態のまま **IAP mode Button を離す。**

これでモジュールは IAP モードとして起動し、UART 経由での書き換え要求を
待ち受ける状態になる。

> 通常の Reset Button 単独押下では、既に書き込まれているユーザ
> ファームウェアが起動する。IAP モードに入るには必ず上記のボタン
> 手順を踏むこと。

### 3.1 IAP モードの起動確認方法

接続している UART に以下の文字列が出力される。

```
IAP
```

この出力を受信できれば IAP モードで起動している。受信できない場合は
ボタン手順、UART の配線、ボーレート設定を再確認すること。

## 4. PC とモジュールを接続する

モジュール側面の **4pin UART コネクタ** に、USB-UART 変換ボードを介して
PC を接続する。

| モジュール側 | 変換ボード側 |
| ------------ | ------------ |
| GND          | GND          |
| TX           | RX           |
| RX           | TX           |
| VCC          | (未接続でよい。モジュールは別電源で動作しているため) |

PC 側の仮想 COM ポートを **115200 bps / 8bit / パリティなし / ストップ 1bit
(8N1) / フロー制御なし** で開く。

115200 bps は ML63Q2537 の UARTF モジュールのハードウェア上限であり、
これ以外の速度は選べない。

### 起動バナー

IAP モードで起動が完了すると、モジュールは UART に以下の文字列を送出する。

```
IAP\r\n
```

このバナーを PC 側のターミナルで受信できれば「IAP モードで待機中」の
合図である。もし受信できない場合は配線 (RX/TX の入れ違い)、ボーレート、
IAP モード起動手順を再確認すること。

## 5. 新しいファームウェアを転送する

IAP はユーザファームウェアイメージを **XMODEM-CRC** で受信する。
以下では代表的なツールでの手順を示す。

### 5.1 Windows: Tera Term を使う

1. Tera Term を起動し、該当の COM ポートを開く。
2. `設定` → `シリアルポート` で 115200 8N1、フロー制御なしを設定。
3. `IAP\r\n` バナーが表示されていることを確認する。
4. メニューから `ファイル` → `転送` → `XMODEM` → `送信` を選択。
5. ダイアログで **オプション「CRC」** を選び、対象の `.bin` ファイルを
   指定する。**チェックサムモードでは動作しない。**
6. 転送が始まる。進捗ダイアログが完了まで進むのを待つ。

### 5.2 Linux: `sx` コマンドを使う

`lrzsz` パッケージに含まれる `sx` を使う。

```bash
# COM デバイスを 115200 8N1 に設定
stty -F /dev/ttyUSB0 115200 cs8 -cstopb -parenb -crtscts raw -echo

# XMODEM-CRC で送信 (--1k を付けると 1024 バイトブロックを併用)
sx -X --1k user_firmware.bin < /dev/ttyUSB0 > /dev/ttyUSB0
```

デバイスパス (`/dev/ttyUSB0`) は環境に応じて置き換える。

### 5.3 プロトコルの詳細

| 項目             | 値                                                                  |
| ---------------- | ------------------------------------------------------------------- |
| フレーミング     | XMODEM-CRC (CRC-16-CCITT、多項式 `0x1021`)                          |
| ブロックサイズ   | 128 バイト (SOH) と 1024 バイト (STX) の両方に対応。混在も可         |
| 開始文字         | 準備完了時に `C` (0x43) を送出                                       |
| ACK / NAK        | CRC 一致で ACK (0x06)、不一致で NAK (0x15)                          |
| ファイル終端     | EOT (0x04) → ACK → 書き込み完了後にリセット                          |
| リトライ         | 1 ブロックあたり最大 10 回まで。11 回連続失敗で転送中止              |
| タイムアウト     | 無通信 10 秒で直前バイトを再送。10 回連続で進捗しなければ中止        |

チェックサム版 XMODEM (CRC なし) は **サポートしない。** 必ず XMODEM-CRC
モードで送信すること。

## 6. ユーザファームウェアイメージの制約

書き込むファームウェアは以下の条件を満たすこと。

| 制約           | 値                                                                       |
| -------------- | ------------------------------------------------------------------------ |
| ファイル形式   | Raw バイナリ (`.bin`)。Intel HEX や ELF は不可                            |
| ベースアドレス | `0x10000000` にリンクすること                                             |
| 最大サイズ     | 240 KB (`0x3C000` バイト)。超えると転送中に拒否される                     |
| パディング     | XMODEM の末尾パディング (`0x1A`) はそのままフラッシュに書き込まれる       |

`0x1003C000` 以降は IAP ファームウェア自身の領域であり、この範囲への
書き込みは IAP 側で自動的に拒否される。

## 7. 転送完了後の動作

### 成功時

最終ブロックと EOT の受信に成功した場合、IAP は以下を実施する。

1. EOT に対して ACK を返す。
2. UART の最終送信が完了するまで待機。
3. ユーザ領域をブート対象に REMAP し、システムリセットを発行する。

次回起動から、新しく書き込んだユーザファームウェアが動作する。IAP
モードは自動的には再入しない。再度 IAP モードに入るには §3 のボタン
手順が必要である。

### 失敗時

CRC 不整合の繰り返し、タイムアウト、範囲外書き込み要求、ベリファイ
失敗のいずれかを検出した場合、IAP は UART に

```
\r\nError\r\n
```

を出力し、モジュール上の `LED1` を点灯させて停止する。復旧するには
**電源を再投入し、再度 IAP モード起動手順から** やり直す。転送途中の
失敗であってもモジュールが起動不能になることはない — IAP 自身は
書き換えられておらず、再度 IAP モードで入り直せる。

## 8. トラブルシューティング

| 症状                                       | 確認ポイント                                                          |
| ------------------------------------------ | --------------------------------------------------------------------- |
| バナー `IAP\r\n` が受信できない            | 配線 (TX↔RX の入れ違い)、ボーレート、IAP モード起動手順               |
| 転送が始まってすぐ NAK が続く              | XMODEM モードが CRC ではなくチェックサムになっていないか              |
| 転送途中で `Error` が返る                  | ファイルサイズが 240 KB を超えていないか、配線ノイズがないか          |
| 転送成功したが新ファームウェアが動かない   | `.bin` が `0x10000000` にリンクされているか、ベクタテーブルの内容     |
| モジュールが応答しない                     | 別電源に切り替え、または USB ケーブル / 変換ボードを別のものへ交換    |
